# 确定性根因诊断与工单闭环

## 当前定位

当前项目尚未获得赛题企业的设备手册、拓扑、告警规则和历史维修工单。因此根因模块使用
内置通用故障模式生成“待验证候选”，不输出设备故障确诊结论。

完整流程为：

```text
异常事件
-> 事件前后测点变化方向和稳健标准差
-> 主导传感器与异常强度
-> 相关性变化和领先时滞
-> 稳定工况或切换期上下文
-> 近期趋势和未来预测风险
-> 通用故障模式匹配
-> 候选根因排序、证据缺口、现场验证步骤
-> 待确认工单草案
```

## 内置模式

模式定义位于 `app/diagnosis/patterns.py`，当前覆盖：

- 阀门卡滞、管路堵塞或出口阻力增大；
- 供给不足、泄漏或泵性能下降；
- 机械负载突增、卡阻或传动部件异常；
- 轴承磨损、转子不平衡或联轴器不对中；
- 负载过高、散热不足或润滑状态恶化；
- 供电波动、电气连接异常或电机负载变化；
- 传感器漂移、安装松动或采集链路异常；
- 多变量工艺耦合变化或未记录的操作事件。

这些规则是工程兜底，不是企业知识库。内置模式的置信度上限为 `0.78`，页面、报告和 API
都会保留来源与使用边界。

## 置信度说明

置信度由以下独立证据累计得到：

- 模式相关物理量是否真正参与异常事件；
- 关键测点类别是否齐全；
- 事件期变化方向是否与模式一致；
- 关系变化与领先时滞是否支持该模式；
- 模式是否覆盖检测器给出的主导传感器；
- 近期趋势和未来预测是否提供持续退化证据；
- 事件是否与工况切换高度重合；
- 单点异常或多变量同步变化是否支持测量链路或工艺变化解释。

置信度只表示“该候选值得以多高优先级进行现场验证”，不能解释为故障发生概率。

## 工单草案

每个异常事件会生成一个 `WorkOrderDraft`，包含：

- 工单编号和事件编号；
- `P1/P2/P3` 优先级；
- 候选根因标题；
- 建议责任角色；
- 按顺序排列的现场动作；
- 支持证据摘要；
- 必须回写的确认结果、处置动作和复测状态。

工单草案会随分析结果写入 PostgreSQL。每条记录使用 `run_id` 与原始工单编号组成全局唯一
`record_id`，支持待确认、已确认、处理中、已完成和已关闭五种状态，并可通过 API 回写
确认根因、处理人员与复测说明。后续增加用户权限和工单签收时保持同一工单协议，无需修改根因
评分主流程。

## 企业知识库接入方式

获得企业资料后应优先新增外部模式加载器，而不是直接修改评分主流程：

1. 把设备手册、报警规则、拓扑和维修案例转成结构化设备专属模式；
2. 每条模式保存设备型号、适用工况、必需测点、方向规则、验证动作和来源版本；
3. 设备专属模式与内置模式使用同一 `FaultPattern` 协议；
4. 只有设备型号、测点和工况匹配时才允许提高置信度上限；
5. 现场确认结果回写后，用于校准规则权重和训练监督排序模型。

大模型继续只负责解释结构化结果和引用知识来源，不能直接读取原始 CSV 并替代确定性计算。
