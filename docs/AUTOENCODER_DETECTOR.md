# 滑动窗口 AutoEncoder 检测器

## 模型定位

`window_autoencoder` 是当前项目的默认非线性时序异常检测器。它不读取故障标签训练，而是从
健康参考数据中学习多传感器在连续窗口内的正常变化规律。与 PCA 只学习线性低维子空间
相比，AutoEncoder 可以表达更复杂的非线性耦合与局部波形。

## 处理流程

```text
多传感器时序
→ 缺失值补齐
→ 局部残差、变化率、波动特征
→ 滑动窗口展平
→ RobustScaler
→ MLP AutoEncoder 健康重构
→ 窗口重构误差
→ 窗口终点风险分数回填
→ 健康分位校准
→ 迟滞阈值、事件合并与传感器归因
```

模型只使用健康参考文件训练；未配置健康文件时，使用当前文件前 25% 作为无监督基线。
每个窗口的重构误差只记录在窗口结束点，保证在线告警不会使用结束点之后的未来数据。
若数据过短、无法形成足够训练窗口，检测器自动回退到 PCA 重构，保证 API 和演示流程不中断。

相同健康基线、特征字段和模型参数会命中进程内 LRU 模型缓存。缓存只保存 scaler、模型和
健康重构误差，不保存待分析文件；首次训练后，批量文件和 API 连续请求可直接复用健康模型。

模型还会以格式版本、SHA-256 校验和和原子写入方式保存到
`outputs/models/window_autoencoder/`。服务重启后可直接恢复；模型结构变化时提升格式版本，
旧模型自动失效并重新训练。训练误差仅保存设备级和传感器级校准序列，真实 8 传感器模型
约 `1.09 MB`，相比保存完整窗口误差矩阵的约 `28 MB` 明显降低。

## 主要参数

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| `autoencoder_window` | 16 | 每个模型样本覆盖的连续采样点数 |
| `autoencoder_hidden` | 24 | 编码器和解码器隐藏层宽度 |
| `autoencoder_bottleneck` | 6 | 压缩健康模式的瓶颈维度 |
| `autoencoder_max_iter` | 250 | 最大训练轮数，启用早停 |
| `autoencoder_max_training_windows` | 3000 | 单次训练使用的最大窗口数 |

## 固定划分实验结果

因果回填版本使用 17 个验证文件选择阈值 `5.5`，随后在 17 个独立测试文件上冻结参数评价：

| 点级 F1 | PR-AUC | 事件级 F1 | 事件召回 | 平均误报事件 | 单文件耗时 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0.3392 | 0.5438 | 0.4500 | 0.9412 | 3.53 | 0.1348 秒（缓存命中） |

相比原默认 Hybrid，事件召回保持 `0.9412`，事件级 F1 从 `0.4382` 提升到 `0.4500`，
平均误报事件从 `4.47` 降到 `3.53`。因此项目默认检测器切换为 AutoEncoder，但 Hybrid、
PCA、MAD 和 Isolation Forest 继续保留为对照与降级能力。

## 当前边界

- 当前实现使用 scikit-learn `MLPRegressor`，部署轻量，适合先完成竞赛工程闭环。
- 实测首次健康模型训练约 3.27 秒，后续同基线文件约 0.17 秒，缓存加速约 19.1 倍。
- `valve2` 场景平均检测延迟仍较高，需要结合窗口长度和告警阈值做延迟专项优化。
- 当前仓库已支持单机跨进程恢复；企业部署还需增加设备 ID、工况 ID、审批状态和模型回滚。
